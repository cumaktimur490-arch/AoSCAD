# Краткий обзор CAD-подходов для AoSCAD Studio

Обзор выполнен по открытым описаниям и исходным репозиториям проектов; это выборка практических принципов, а не сравнение возможностей по маркетинговым материалам.

| Программа / проект | Полезный для AoSCAD подход | Вывод для отдельного приложения |
|---|---|---|
| [FreeCAD](https://github.com/FreeCAD/FreeCAD) | Параметрические объекты, история модели и переход от эскиза к 3D. Проект построен на Open CASCADE и Qt. | Сохранять параметры рядом с BREP-геометрией и позволить менять размеры созданных объектов без повторного импорта. |
| [SolveSpace](https://github.com/solvespace/solvespace) | Параметрическое 2D/3D-проектирование с ограничениями и решателем. | Эскизы с ограничениями — важный следующий этап, но не стоит имитировать их без геометрического решателя. |
| [OpenSCAD](https://github.com/openscad/openscad) | Явные числовые параметры и последовательное построение тела из примитивов и операций CSG. | Сделать размеры примитивов видимыми и редактируемыми; это небольшое, проверяемое развитие текущего BREP-редактора. |
| [LibreCAD](https://github.com/LibreCAD/LibreCAD) | Отдельное настольное CAD-приложение; практичная ориентация на обмен DXF и пакетные преобразования. | Поддерживать AoSCAD как самостоятельную программу и явно объяснять границы обменных форматов. |
| [KiCad](https://github.com/KiCad/kicad-source-mirror) | Проектный подход с несколькими специализированными редакторами и отдельным 3D-просмотром. | Сохранять связанное состояние проекта и геометрию вместе; не смешивать CAD-модель с произвольными временными данными. |
| [Open CASCADE Technology](https://github.com/Open-Cascade-SAS/OCCT) | Геометрическое ядро для 3D-моделирования, обмена CAD-данными и визуализации; используется в C++-приложениях. | Продолжать использовать OCCT для BREP, STEP/IGES и расчёта площадей, объёмов и габаритов. |

## Принятые решения

1. AoSCAD Studio остаётся самостоятельным нативным приложением на C++ / Qt / Open CASCADE, а не дополнением для другой CAD-системы.
2. Для локальных примитивов добавлены редактируемые параметры и сохранение их вместе с точной BREP-геометрией. Формат проекта `.aoscad` — версия 4; проекты версий 2 и 3 продолжают открываться.
3. Инспектор показывает площадь, объём, габариты и оценку массы по выбранному материалу. Масса помечается как оценочная; для открытой сетки объём может быть недоступен.
4. Для SolidWorks, T-FLEX CAD и других систем сохраняется нейтральный путь обмена через STEP AP214/AP242 или IGES. Нативные проприетарные форматы не заявляются как поддерживаемые.
5. Первый рабочий набор B-Rep операций теперь реализуется через Open CASCADE, а не имитируется кнопками: булевы объединение/вычитание/пересечение, фаска и скругление всех рёбер, линейный массив по глобальным осям и зеркальная копия по глобальным плоскостям. Ограничения текущей реализации описаны ниже.
6. Произвольный sketch solver, устойчивые ссылки на топологию, оболочка/отверстие/уклон, сборки и чертежи требуют отдельного моделирования и проверки; готовность этих функций не предполагается.
7. Обновление поставляется отдельной небольшой Windows-программой. Она скачивает опубликованный установщик с GitHub Releases и проверяет его SHA-256 по release-манифесту; при запуске из AoSCAD Studio ждёт закрытия приложения перед тихой установкой.

## Первый функциональный набор моделирования

Алгоритмы выполняются в `CadIO` через ядро OCCT: [булевы операции](https://dev.opencascade.org/doc/overview/html/occt_user_guides__modeling_algos.html), [скругление](https://dev.opencascade.org/doc/refman/html/class_b_rep_fillet_a_p_i___make_fillet.html), [фаска](https://dev.opencascade.org/doc/refman/html/class_b_rep_fillet_a_p_i___make_chamfer.html) и [геометрические преобразования](https://dev.opencascade.org/doc/refman/html/class_b_rep_builder_a_p_i___transform.html). Каждая новая операция — фича с UUID-входом, параметрами и повторным вычислением; если OCCT вернул пустую/невалидную геометрию либо нулевой объём, пересчёт не публикует частично изменённый документ.

Текущая функциональная граница намеренно узкая и явная:

- Boolean union/cut/common принимает два объёмных тела. Для cut первый список/комбо-пункт — основание, второй — инструмент.
- Fillet/chamfer выполняется сразу на всех топологических рёбрах тела. Применение ко всем рёбрам иногда геометрически невозможно; тогда операция отклоняется. Выбор части рёбер требует отдельного edge-picking и устойчивой топологической адресации.
- Linear pattern создаёт 2–100 экземпляров вдоль глобальных X/Y/Z с положительным шагом; mirror-копия отражает оригинал через глобальную XY/YZ/ZX. Это compound с несколькими телами, не объединение пересекающихся копий.
- Скругление, фаска и шаг/количество массива редактируются после построения в Inspector; изменения upstream-фич пересчитывают dependent nodes. Параметры и ссылки сохраняются в текущем `.aoscad` v4.

Тесты в `native/tests/CadModelTests.cpp` проверяют объёмы и габариты, зависимость Boolean от трансформации входа, транзакционный отказ пустого пересечения и round-trip feature graph. До выполнения Windows CI сборка и runtime не считаются подтверждёнными; новые возможности не следует называть безошибочными или промышленными.
